# 低空智瞰运营手册

## 定位与边界

**一句话定位：** 低空智瞰是低空产业的政策落地雷达与商业算账本，为无人机、eVTOL、通航从业者和地方产业管理者，把政策与项目拆到“谁能做、怎么做、需要什么条件、账能否算通”。

核心读者是低空产业链企业负责人、市场/战略/运营岗位，应用侧项目负责人，以及地方低空管理、园区招商与产业研究人员。不是面向股民的概念炒作号，也不是通稿搬运号。

内容必须回答至少一个问题：

- 政策到底改变了哪条规则，谁要在什么时间采取行动？
- 企业或项目处于意向、试点、订单、交付还是确认收入阶段？
- 一个场景的技术、审批、人员、保险、运维和成本条件能否闭环？
- 不同城市、方案或产业环节在同一口径下有什么差异？

不评股价、不做收益承诺、不替代飞行审批或法律意见，不传播未经核验的事故、空域、军事或企业经营信息。

## 原始来源与素材卡

按可靠性处理素材。

| 等级 | 可用来源 | 使用规则 |
|---|---|---|
| A | 国家部委、民航局及 UOM、地方政府、公共资源交易平台、政府采购网、上市公司公告/年报/招股书、企业适航证书与官方产品资料 | 可直接支撑事实；保留原始链接和日期。 |
| B | 招标/中标公告、企业新闻稿、投资机构公告、行业协会、展会演讲材料、论文与白皮书 | 用于确认商业进展；说明来源属性。 |
| C | 行业媒体、其他公众号、短视频、自媒体、聚合站 | 仅作线索；关键结论必须回到 A 或 B 级来源。 |

素材卡字段：事件、发布日期、发生日期、地区、企业/机构、产业环节、金额、数量、应用场景、原始链接、来源等级、可验证事实、尚未验证信息、可能影响、更新时间。

## 栏目骨架

### 政策雷达

`一句结论 → 政策原文与变化 → 对谁产生影响 → 可执行机会/约束 → 后续观察指标 → 来源`

### 企业拆解

`核心判断 → 产品与位置 → 客户/订单/收入证据 → 竞争与风险 → 需要继续验证的指标 → 来源`

不要将签约、意向、试点、订单、收入混为一谈。

### 场景账本

`问题与结论 → 传统方式成本 → 低空方案成本（设备、人力、审批、运维）→ 关键假设 → 回本条件 → 不适用边界 → 来源`

### 数据图谱/实用工具

`读者能用它做什么 → 覆盖范围与统计口径 → 数据表/图 → 字段解释 → 缺口与更新规则 → 来源`

### 情报周报

每条 100–200 字：`事实 → 判断 → 下一步看什么`。优先 5 条有后续影响的事情，避免新闻罗列。

## 冷启动发布节奏

账号目前缺少真实内容与读者数据，先执行每周三篇，连续四周后再决定是否加量：

| 时间 | 栏目 | 自动化要求 |
|---|---|---|
| 周一 07:45 | 政策雷达 | 只选近 14 天内有原文的一项政策/标准/征求意见；至少 2 个 A 级来源。 |
| 周三 20:30 | 智瞰深一度 | 企业、城市或场景拆解；至少 2 个 A/B 级独立来源，关键数字可复算。 |
| 周五 17:00 | 一周低空情报 | 3–5 条真正影响决策的信号；每条标事实、判断、观察指标。 |

周二、周四、周六用于建立素材卡、补证据和维护数据库；周日不自动推稿，只复盘。重大政策可触发加更，但仍须满足来源与校验门槛。

自动化的目标是稳定产出“值得人工审核的草稿”，不是追求日更数量。当天没有合格选题时，应跳过并说明缺少什么证据。

## 标题评分表

每篇先写正文结论，再拟 10 个标题。每项 0–20 分，总分低于 80 不使用。

| 维度 | 判断问题 |
|---|---|
| 准确 | 标题是否被正文和来源支撑？ |
| 具体 | 是否有对象、范围、时间或量化信息？ |
| 读者收益 | 读完能获得什么判断或行动？ |
| 信息差 | 是否给出非显而易见但可证实的发现？ |
| 一致性 | 是否承诺了正文真正回答的问题？ |

常用结构：

- `数据 + 对象 + 结论`：31 省政策对比后能得出什么。
- `变化 + 影响对象 + 后果`：新规变化后运营企业要补什么。
- `场景 + 经济账`：一单成本、临界密度或回本条件。
- `反常识 + 证据`：看起来热门的环节为何未必先赚钱。
- `清单 + 使用价值`：项目申报前需准备哪些可核验材料。

## 发布前检查

- 关键事实有原始出处、日期与原句或数据位置。
- 政策、项目、订单、收入的阶段没有混淆。
- 标题与正文一致，没有把判断写成已发生的事实。
- 每个段落都推进论点；删除套话、重复、无证据的预测和堆砌形容词。
- 至少有一个具体数据、案例或原始材料支撑核心判断。
- 移动端检查标题层级、留白、表格可读性、图片版权与图注。
- 文末含数据来源、更新时间、免责声明；交付为草稿等待人工审核发布。
- 自动化稿必须通过 `scripts/validate_article.py`；校验失败时不得调用草稿接口。
